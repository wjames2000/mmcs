# 多模型协作系统 —— 需求规格说明书

## 1. 引言

### 1.1 编写目的

本文档旨在对「多模型圆桌会议系统」进行完整的**功能规格定义**，作为后续系统设计、开发实现和验收测试的基线依据。读者包括项目团队、架构师、开发工程师、测试工程师及产品负责人。

### 1.2 项目背景

团队在日常工作中频繁进行头脑风暴、代码评审、产品决策分析等高智力密度的协作。传统方式依赖人工组织会议，存在同步等待成本高、思维角度受限、讨论结构松散、结论整理耗时等痛点。本项目旨在构建一个 AI 驱动的多模型圆桌会议系统，提供永不断电的 AI 专家组，按结构化流程进行多轮辩论、评审或头脑风暴，最终产出带完整推理链的决策建议。

### 1.3 定义与术语

| 术语 | 说明 |
|------|------|
| Agent | 具备自主推理和执行能力的 AI 智能体，可绑定特定大模型和角色配置 |
| Eino | 字节跳动开源的应用框架，提供 ChatModel、Graph、ADK 等核心编排能力 |
| ChatModel | Eino 中的大模型组件抽象，支持 OpenAI、Claude、Ollama 等多种提供商 |
| Graph | Eino 的有向图编排引擎，支持条件分支、循环、流式处理和全局状态 |

| Workflow | Eino 的工作流抽象，以结构体字段映射方式进行 DAG 编排 |

| 工作区 (Workspace) | 多轮对话或多个议题的分区管理容器，一个工作区可包含多个讨论会话，也可一个会话独占一个工作区 |

## 2. 总体描述

### 2.1 产品概述

多模型协作系统是一个**以工作区（Workspace）为组织单元**的 AI 协作平台。工作区是讨论会话的容器，支持两种模式：一次会议独占一个工作区（独立议题），或多个会议共享一个工作区（多轮对话 / 多议题分区管理）。用户在工作区内创建讨论会议，配置 AI 专家角色及其绑定的模型，选择或自定义讨论范式，系统按结构化流程驱动各角色发言并输出带推理链的结论。讨论结束后，结论自动转为可追踪执行的任务，由 Agent 执行并由验证官 Agent 闭环验证。

### 2.2 用户特征

| 用户类型 | 核心诉求 | 使用频率 |
|---------|---------|---------|
| 研发 Team Leader | 代码评审、技术方案决策 | 高频 |
| 产品经理 | 产品决策、用户需求分析 | 中频 |
| 技术负责人 | 技术选型、架构评审 | 中频 |
| 团队成员 | 参与脑暴、讨论 | 按需 |

### 2.3 假设与依赖

- 各 AI 模型 API 服务可用，网络延迟在可接受范围内
- 系统支持本地部署模型（Ollama）以及商业 API 两种接入方式
- 用户的 API Key 等凭据加密存储，不暴露于前端
- 系统运行于服务端，前端通过 WebSocket / SSE 与后端通信

### 4.2 工作区管理模块

**功能描述：** 工作区是讨论会话的顶级容器，用于对多轮对话或多个议题进行分区管理。支持两种组织模式：
- **独立模式（Standalone）**：一次讨论会议独占一个工作区，适用于单次议题明确的讨论（如一次代码评审）
- **共享模式（Shared）**：多个讨论会议共享一个工作区，适用于复杂项目的多轮、多议题协作（如产品从需求分析到技术评审再到复盘的全过程）

用户可在工作区内浏览所有关联会话、查看跨会话的任务汇总视图、管理工作区级别的角色模板和模型配置。

**输入/输出规格：**

| 操作 | 输入 | 输出 |
|------|------|------|
| 创建工作区 | 名称、描述、组织模式（独立/共享）、成员列表 | WorkspaceID |
| 获取工作区 | WorkspaceID | 工作区详情（含关联会话摘要） |
| 更新工作区 | WorkspaceID + 配置 | 更新后的工作区 |
| 归档工作区 | WorkspaceID | 工作区标记归档，会话不可再启动 |
| 关联会话 | WorkspaceID + SessionID | 会话加入工作区 |
| 获取工作区任务汇总 | WorkspaceID | 该工作区下所有任务的聚合视图 |

**数据模型（Go struct）：**

```go
type Workspace struct {
    ID        string          `json:"id"`
    Name      string          `json:"name"`
    Desc      string          `json:"description"`
    Mode      WorkspaceMode   `json:"mode"`    // standalone / shared
    Status    WorkspaceStatus `json:"status"`  // active / archived
    Members   []string        `json:"members"`
    CreatorID string          `json:"creator_id"`
    CreatedAt time.Time       `json:"created_at"`
    UpdatedAt time.Time       `json:"updated_at"`
}

type WorkspaceMode string
const (
    WorkspaceStandalone WorkspaceMode = "standalone"
    WorkspaceShared     WorkspaceMode = "shared"
)

type WorkspaceStatus string
const (
    WorkspaceActive   WorkspaceStatus = "active"
    WorkspaceArchived WorkspaceStatus = "archived"
)
```

**与会话管理的关系：**

工作区与讨论会话为 **1:N** 关系。会话创建时可指定所属工作区，也可后续关联。工作区为上层组织单元，不参与 Eino Graph 编排，而是通过会话的 `workspace_id` 字段建立关联，在 UI 层提供分区导航和聚合视图。

### 4.3 会话管理模块

**功能描述：** 管理讨论会议的全生命周期，包括创建、配置、启动、暂停、终止、归档。

**输入/输出规格：**

| 操作 | 输入 | 输出 |
|------|------|------|
| 创建会话 | 会话名称、讨论范式、角色列表、模型绑定配置 | SessionID、初始状态 |
| 启动会话 | SessionID | Graph 开始执行，流式输出启动 |
| 暂停会话 | SessionID | Graph 节点暂停（Interrupt） |
| 恢复会话 | SessionID + 用户输入 | Graph 从断点恢复（Resume） |
| 终止会话 | SessionID | Graph 停止，触发 Summarize 节点 |

**Eino 实现方案：**

```go
// Session 对应一个 Graph 实例
type Session struct {
    ID        string
    Graph     *eino.Graph
    State     *SessionState
    Roles     []*RoleConfig
    Paradigm  ParadigmType
    CreatedAt time.Time
}

// 使用 Eino Graph 构建会话流程
func NewSession(config *SessionConfig) (*Session, error) {
    graph := eino.NewGraph()
    // 添加讨论流程节点
    graph.AddNode("context_init", NewContextInitNode(config))
    graph.AddNode("round_start", NewRoundStartNode(config))
    graph.AddNode("expert_speak", NewExpertSpeakNode(config.Roles))
    graph.AddNode("moderator_eval", NewModeratorEvalNode(config))
    graph.AddNode("summarize", NewSummarizeNode(config))

    // 定义节点间的边
    graph.AddEdge("context_init", "round_start")
    graph.AddEdge("round_start", "expert_speak")
    graph.AddEdge("expert_speak", "moderator_eval")
    graph.AddConditionalEdge("moderator_eval", "round_start", ShouldContinue)
    graph.AddEdge("moderator_eval", "summarize")

    return &Session{
        ID:    GenerateID(),
        Graph: graph,
        State: NewSessionState(),
    }, nil
}
```

### 4.4 角色引擎模块

**功能描述：** 管理 AI 专家角色的定义、配置、存储和复用。每个角色包含身份信息、人格特质、知识领域、说话风格、绑定的模型、系统提示词模板，以及可选的**技能加载**——角色可引用一个或多个外部 Skill，Skill 内容自动注入系统提示词，赋予角色特定的专业能力。

**数据模型（Go struct）：**

```go
type Role struct {
    ID            string            `json:"id" bson:"_id"`
    Name          string            `json:"name"`           // 角色名称，如「安全审查员」
    Title         string            `json:"title"`          // 职位头衔
    Traits        RoleTraits        `json:"traits"`         // 核心特质
    Expertise     []string          `json:"expertise"`      // 专业知识领域标签
    SpeakingStyle string            `json:"speaking_style"` // 说话风格描述
    ModelBinding  ModelBinding      `json:"model_binding"`  // 绑定的模型配置
    SystemPrompt  string            `json:"system_prompt"`  // 系统提示词模板
    Skills        []string          `json:"skills"`         // 引用的 Skill 名称列表
    CreatorID     string            `json:"creator_id"`
    CreatedAt     time.Time         `json:"created_at"`
    UpdatedAt     time.Time         `json:"updated_at"`
}

type RoleTraits struct {
    Aggressiveness int  // 激进程度 1-10
    Optimism       int  // 乐观程度 1-10
    Creativity     int  // 创意程度 1-10
    Detail         int  // 细节关注度 1-10
}

type ModelBinding struct {
    Provider   ModelProvider // OpenAI / Anthropic / Ollama / Ark
    ModelName  string        // gpt-4o / claude-3.5-sonnet / deepseek-coder
```

```go
%s

%s

%s

    tmpl := chat_template.NewChatTemplate(
        chat_template.WithSystemTemplate(
            chat_template.NewMessageTemplate(systemMsg),
        ),
    )
    return tmpl
}
```

### 4.5 讨论编排模块

**功能描述：** 核心编排引擎，驱动多角色按预定义范式进行结构化讨论。支持以下讨论范式：

**4.5.1 轮询发言范式（RoundRobin）**

```
流程：按固定顺序依次发言，每轮每人发言一次
适用：创意脑暴、信息收集
Graph 结构：
  RoundStart → [Expert1 → Expert2 → ... → ExpertN] → ModeratorSummary → [继续/结束]
```

**Eino 实现：** 使用 `Graph` + `AddBranch` 条件分支实现轮次控制

```go
func BuildRoundRobinGraph(roles []*Role) (*eino.Graph, error) {
    graph := eino.NewGraph()
    graph.AddNode("round_start", NewRoundStartNode())

    // 为每个角色添加并行发言节点
    parallel := eino.NewParallel()
    for i, role := range roles {
        node := NewExpertNode(role)
        graph.AddNode(fmt.Sprintf("expert_%d", i), node)
        parallel.AddBranch(fmt.Sprintf("expert_%d", i))
    }
    graph.AddNode("parallel_speak", parallel)
    graph.AddNode("moderator", NewModeratorNode())

    graph.AddEdge("round_start", "parallel_speak")
    graph.AddEdge("parallel_speak", "moderator")

    // 条件分支：继续下一轮或结束
    graph.AddBranch("moderator", map[string]string{
        "continue": "round_start",
        "end":      "summarize",
    }, EvaluateRoundCondition)

    graph.AddNode("summarize", NewSummarizeNode())
    return graph, nil
}
```

**4.5.2 模拟法庭范式（CourtSimulation）**

```
流程：
  1. 陈述阶段：代码作者/方案提出者说明设计意图和上下文
  2. 交叉质询：各审查员依次独立发言，必须引用具体证据
  3. 回应阶段：作者逐条回应是否采纳及原因
  4. 总结阶段：主持 AI 汇总未解决问题，给出质量评分
适用：代码评审、方案审查
```

**Eino 实现：** 使用 `SupervisorAgent` 作为主持人，`ChatModelAgent` 作为审查员

```go
func BuildCodeReviewGraph(codeContent string, roles []*Role) (*eino.Graph, error) {
    graph := eino.NewGraph()

    // 阶段 1：作者陈述
    graph.AddNode("author_statement", NewStatementNode())
    // 阶段 2：审查员并行审查（每个审查员绑定不同 ChatModel）
    reviewParallel := eino.NewParallel()
    for i, reviewer := range roles {
        agent := NewReviewerAgent(reviewer)
        reviewParallel.AddBranch(fmt.Sprintf("reviewer_%d", i))
    }
    graph.AddNode("review_phase", reviewParallel)
    // 阶段 3：作者回应
    graph.AddNode("author_response", NewResponseNode())
    // 阶段 4：主持 AI 汇总（SupervisorAgent）
    graph.AddNode("final_summary", NewCodeReviewSummaryNode())

    graph.AddEdge("author_statement", "review_phase")
    graph.AddEdge("review_phase", "author_response")
    graph.AddEdge("author_response", "final_summary")

    return graph, nil
}
```

```go
    wf.AddNode("score_adjustment", NewAdjustmentNode()).
        MapFields(func(challenges any) map[string]any {
```

### 4.9 验证闭环模块

**功能描述：** 配置一个专用的「验证官」Agent，负责检查任务完成度，按验收标准和原始结论自动判定任务状态，结果同步到 Todo List 面板。

**验证流程：**

```

         ↓
验证官读取任务详情 + 验收标准 + 执行结果
         ↓
验证官判定：通过 / 需修改 / 不通过
         ↓
同步结果到 Todo List 面板
         ↓
如不通过 → 任务退回执行 Agent 重新处理
```

**Eino 实现方案：**

```go
// 验证官作为一个独立的 ChatModelAgent

- 部分满足但有明确修改方案 → 需修改
```

## 9. 附录

### 附录 A：Eino 核心概念速查

| 概念 | 说明 | 本项目使用场景 |
|------|------|--------------|
| `ChatModel` | 大语言模型抽象，支持 Generate 和 Stream | 每个角色绑定一个 ChatModel 实例 |
| `Graph` | 有向图编排，支持条件分支和循环 | 讨论流程编排 |
| `Chain` | 线性流水线，节点顺序执行 | 简单预处理/后处理流水线 |
| `Workflow` | 结构体字段级映射的 DAG | 评分聚合、决策矩阵计算 |
| `ChatTemplate` | 提示词模板，支持 System/User/Assistant 消息 | 角色系统提示词构建 |
| `Tool` | 工具调用接口 | Agent 操作（数据库查询、API 调用） |
| `Lambda` | 用户自定义函数节点 | 数据转换、验证、格式化 |
| `Agent` | ADK 智能体抽象（ChatModelAgent 等） | 讨论参与者、任务执行 Agent |
| `SupervisorAgent` | 分层协调 Agent | 讨论主持人、辩论裁判 |
| `DeepAgent` | 复杂任务分解 Agent | 多步骤协作任务 |
| `PlanExecuteAgent` | 规划-执行-再规划循环 | 结论转任务 |
| `Interrupt/Resume` | 暂停/恢复机制，支持人类介入 | 用户打断讨论并插入意见 |
| `Callbacks` | 钩子系统，监听执行过程 | 过程追踪、审计日志 |
